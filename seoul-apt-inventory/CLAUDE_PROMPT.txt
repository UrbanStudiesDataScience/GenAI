첨부 ZIP을 압축 해제하고 이 지시문, 02_작업설정.json, 공식자료 탐색가이드, 검증 기준, 빈 양식 및 입력규격을 읽은 뒤 작업해줘.

[목표]
공식 공동주택공시가격 데이터를 직접 찾아 다운로드하고, 서울특별시 아파트의 ‘단지×정확한 전용면적형별 세대수와 특성’ 엑셀을 만들어줘. 사용자는 실거래 CSV를 이미 확보했고, 이번에는 공시가격 기반 재고표만 필요하다. 실거래 CSV를 다시 요구하지 마. 원 공시가격 파일을 사용자에게 먼저 달라고 요청하지 말고, 네가 가능한 검색·웹·코드 실행·다운로드 도구로 확보부터 진행해줘.

설명이나 계획만 제시하고 끝내지 말고, 실제 다운로드·집계·검증·파일 생성까지 수행해줘. 전체 작업이 길면 중간 산출물과 진행 기록을 저장하고 계속 진행해줘. 최종 자료를 확보하지 못했다면 그 사실과 막힌 단계를 정확하게 표시해줘.

[1. 작업범위 및 기준시점]
- 대상은 서울특별시의 아파트 재고다. 이후 매매가격 분석에 사용할 것이지만 공시자료를 ‘매매 거래가 있었던 주택’으로 제한하지 마.
- 단지×전용면적형별 세대수의 주 자료는 공동주택공시가격 데이터다.
- K-apt, 건축물대장, 주소·공간정보 등의 공식 자료는 단지 식별, 아파트 분류, 준공일, 좌표 등 특성 보완에 활용해줘.
- K-apt에 연결되지 않았다는 이유만으로 공시자료의 아파트를 제거하지 마.
- 사용자 지정 기준연도가 없으므로 실행일 현재 공식적으로 내려받을 수 있는 최신의 ‘서울 전체를 포괄하는 완결 정기 공시 기준자료’를 기본으로 선택해줘. 가장 최근 제목만 보고 일부 자치구·일부 추가공시 자료를 전체 재고로 선택하면 안 된다.
- 실제 선택한 연도, 공시기준일, 정기/추가/정정 구분, 지역별 완결성, 선택 근거를 기록해줘. 최신 연도가 불완전하면 최신의 완결 연도를 사용하고 이유를 남겨줘.
- 여러 연도나 기준일을 단순 합산하지 마. 추가·정정 자료는 동일 주택의 중복, 신규 편입, 교체 관계를 확인해야 한다. 정기 기준자료와 추가 반영 재고는 섞지 말고 필요하면 별도 결과로 구분해줘.
- 기존 분석 노트북에서 사용한 ‘2024’ 명칭의 엑셀 원본은 제공되지 않았다. 파일명만으로 2024-01-01 재고라고 가정하지 말고, 이번에 만든 공시재고를 기존 원마스터와 동일하다고 표현하지 마.

[2. 자료 검색과 다운로드를 직접 수행]
공공데이터포털, 부동산공시가격알리미, 한국부동산원, 브이월드 등 공식 제공처를 조사해줘. ZIP의 03_공식자료_탐색가이드.md는 탐색 출발점이며, 실제 파일/API 주소와 제공 방식은 현재 사이트에서 확인해야 한다.

우선순위:
1) 서울 전체 또는 자치구별로 내려받을 수 있는 공식 대용량 파일
2) 전국 공식 파일을 내려받아 서울을 추출
3) 필요한 상세 필드를 제공하는 공식 API

자료명에 ‘공동주택가격’이 들어 있어도 평균·통계·단지별 요약만 있는 자료로는 정확한 면적형 세대수를 복원할 수 없다. 반드시 공식 컬럼설명과 실제 표본을 읽고 집계 가능성을 판단해줘.

- 검색결과 URL, 데이터 소개 페이지, 실제 다운로드/API URL을 구분해서 기록해줘.
- HTTP 200만으로 다운로드 성공이라고 판단하지 마. 로그인 HTML, 오류 HTML, 빈 응답인지 검사하고 실제 파일 유형·용량·행 수·컬럼을 확인해줘.
- 압축파일은 해제한 파일 목록까지 확인해줘.
- API는 전체 페이지·지역 분할을 수집하고 서버의 총건수와 비교해줘. 빈 페이지나 호출제한을 정상 완료로 간주하지 마.
- 원본은 raw/에 보존하고 URL·조회일시·파일명·크기·SHA-256·기준시점·라이선스를 source_manifest.csv에 기록해줘.
- 코드는 재시도·이어받기·캐시를 적절히 사용하고 같은 파일을 재다운로드해 두 번 집계하지 마.
- 인증이 필요하면 우선 공개된 파일·공식 대체경로를 찾아줘. 공개 경로로 해결되지 않을 때만 정확한 사이트, 데이터명, 필요한 인증/키/도구, 실제 오류와 사용자에게 필요한 최소 조치를 한 번에 알려줘. 키 값은 로그나 결과 파일에 저장하지 마.
- 현재 환경에 웹/네트워크 또는 파일 작성 기능이 없으면 가능한 작업과 불가능한 작업을 구분하고, 진행한 것처럼 꾸미지 마. 자료를 받지 못한 상태에서 가상 수치로 최종 재고표를 채우지 마.

[3. 원자료 행 단위와 아파트 범위 확인]
공식 설명서와 실제 표본으로 다음을 확인해줘.
- 한 행이 주택 한 호인지, 소유권 지분인지, 공시 이력인지, 집계행인지
- 주택/건물/단지 고유식별자와 주소·동·호 공개 여부
- 주택유형에서 아파트를 연립·다세대와 구분할 수 있는지
- 전용면적, 가격, 기준일, 정정 구분 등의 의미와 단위

서울 25개 자치구를 확인하고 지역별 건수를 보고해줘. 주택유형 필드가 없다면 공식 보조자료로 아파트 여부를 확인해줘. 단지명에 ‘아파트’라는 단어가 있다는 이유만으로 유형을 확정하지 마. 미분류 주택은 별도 보관하고 건수를 남겨줘.

[4. 개별 주택 식별 및 중복처리]
- 신뢰 가능한 원천 주택ID가 있으면 우선 사용해줘.
- 없으면 법정동·지번·건물 식별정보·동·호 등 사용 가능한 필드로 주택 식별키를 검증해줘.
- 공시연도·차수·정정·소유자 지분별 행이 같은 주택을 반복하는지 확인해줘.
- 면적과 공시가격이 같다는 이유로 서로 다른 세대를 중복제거하면 안 된다.
- 동·호나 고유ID가 비공개여도 공식 설명상 1행=1호인 자료일 수 있다. 동일 값 행을 일괄 drop_duplicates하지 말고 실제 중복을 입증할 수 있는 경우만 제거해줘.
- 공식 집계자료를 쓰는 경우에는 정확한 전용면적별 세대수 필드가 있어야 하며, 그 공식 세대수 필드를 합산해줘. 한 행을 무조건 한 세대로 세지 마.
- 행 단위를 확인하지 못하면 최종 unit_count를 확정하지 말고 막힌 이유를 보고해줘.
- 모든 필터·중복 제거·정정 적용의 전후 건수와 판단 규칙을 기록해줘.

[5. 단지 식별과 정수ID]
- 단지명 하나로 그룹화하지 말고 공식 단지코드와 검증한 주소·건물 연결관계를 사용해줘.
- 동일 이름의 서로 다른 단지, 동일 주소의 여러 단지, 복수 지번을 쓰는 한 단지, 차수·블록, 재건축 전후를 구분해줘.
- 공시자료의 개별 건물ID를 곧바로 단지ID라고 가정하지 마.
- 근거가 모호한 통합·분리는 review_needed에 남겨줘.
- 공식 원천코드를 보존하고 별도로 danji_uid 정수ID를 부여해줘.
- id_crosswalk.csv를 저장하고 재실행·신규단지 추가 때 기존 숫자가 바뀌지 않도록 해줘.
- danji_name은 자치구+법정동+표준단지명으로 구성하고 필요한 구분을 더해 유일하게 관리해줘.
- 지번의 앞자리 0, 본번/부번, 산 여부, 법정동코드를 원본과 함께 보존해줘.

[6. 전용면적형별 세대수]
집계키는 [danji_uid, 전용면적]이다.

- 전용면적은 원자료 소수 정밀도를 보존해줘. 가능한 한 Decimal 또는 원문 기반의 정확한 정규화를 사용해줘.
- 84.990과 84.99는 같은 숫자로 처리하되, 84.99와 84.98은 임의로 합치지 마.
- 공급면적·계약면적을 전용면적으로 사용하지 마.
- 같은 단지·같은 전용면적에 여러 동/평면형이 있으면 중복 없는 실제 주택 수를 합산해줘.
- unit_count = 해당 단지·해당 전용면적의 개별 아파트 주택 수.
- gen_count = 선택한 공시기준 자료에서 확인되어 최종 포함된 해당 단지 전체 아파트 주택 수 = Σ unit_count.
- 공식 총세대수가 별도로 확인되면 official_gen_count로 기록하고, 두 값의 차이를 보고해줘. 원 분석모형의 총세대수와 이번 공시자료 관측세대수가 반드시 같다고 가정하지 마.
- K-apt의 면적구간별 세대수, 실거래의 면적별 거래비율, 전체 세대수의 균등분배로 unit_count를 대체하지 마.
- 주택유형/단지/면적이 미확정된 행을 최종 포함 집계에서 제외할 경우 그 행수와 잠재 세대수는 별도 보고해줘.

[7. 특성 보완]
공식 자료에서 가능한 한 다음을 보완해줘.
- 표준 지번주소 및 도로명주소
- 준공 관련 날짜(사용승인일 등), 준공연도
- 위도·경도(WGS84)
- 공식 단지코드 및 공식 총세대수

주소 매칭은 근거를 기록하고 유사한 이름/가까운 좌표만으로 다른 단지를 연결하지 마. 보완자료가 K-apt 비포괄 소규모 단지를 누락시키지 않도록 주의해줘.

없는 값은 빈칸과 사유로 남겨줘. 공시연도를 준공연도로 쓰거나 연도만 아는 날짜를 YYYY0101로 만들지 마. 자치구 중심점 같은 값을 단지 좌표로 채우지 마. 확인한 준공연도만 있으면 built_year와 날짜 정밀도에 따로 기록해줘.

준공일·좌표가 없더라도 확인된 세대수 재고행은 inventory에서 보존하고 data_status와 missing_fields로 표시해줘. 모형입력이 모두 갖춰진 행만 별도 model_ready.csv로 제공하고, 원재고에서 빠진 단지/세대수를 보고해줘.

[8. 결과 엑셀 및 데이터 형식]
파일명: seoul_apt_inventory_<기준연도>_<공시기준일>.xlsx

첫 번째 시트 inventory의 선두 컬럼은 다음 순서로 맞춰줘.
danji_uid, danji_name, 전용면적, unit_count, gen_count, built, lat, lon, gun, gu, adr_index1

의미:
- danji_uid: 분석용 정수 단지ID
- danji_name: 유일한 표준단지명
- 전용면적: 소수 보존한 ㎡ 전용면적
- unit_count: 해당 면적형 세대수
- gen_count: 공시자료에서 최종 관측·포함한 단지 전체 세대수
- built: 확인한 날짜만 YYYYMMDD; 부분 날짜는 빈칸
- lat/lon: 확인한 WGS84 위도·경도
- gun: 자치구(예: 강남구)
- gu: 법정동(예: 대치동)
- adr_index1: 표준 지번주소

기존 코드 이름과 맞추기 위해 gun=자치구, gu=법정동을 유지해줘.

추가 컬럼:
source_complex_id, kapt_code, 도로명주소, 기준연도, 공시기준일,
release_type, official_gen_count, gen_count_source, built_year,
built_date_type, coordinate_source, data_status, missing_fields,
count_source_id, attribute_source_ids

시트 순서:
1) inventory: 검증한 단지×면적형별 재고. 일부 특성 미확인은 상태로 표시
2) complex_summary: 단지별 세대수·면적형수·주소·면적범위·특성 완성도·공식 총세대수와의 차이
3) review_needed: 미분류·모호한 단지/중복/면적/특성/재고범위 문제와 조치
4) source_and_rules: 원천, 컬럼대응, 기준시점, 집계·정정·중복·제외 규칙

ZIP의 빈 엑셀은 헤더/형식 참고용이며 실제 데이터가 아니다. 컬럼·시트 순서를 유지하고 필요한 감사 시트는 추가할 수 있다. 공시가격을 요약해 부가 컬럼으로 넣는다면 단위를 명시하고 공시가격이라고 이름 붙여줘. 매매가격/실거래가격으로 취급하지 마.

[9. 필수 검증]
04_검증및납품기준.md에 따라 수행해줘.
- 키 유일성, 양수 정수 세대수, 정확한 면적 정규화
- 단지별 Σ unit_count = gen_count
- 전체 unit_count 합계 = 집계 직전 포함 주택수 또는 검증한 공식 세대수 합계
- 원자료 → 기준시점 → 서울 → 아파트 → 중복/정정 처리 → 확정단지/면적 → inventory의 단계별 건수
- 서울 25개 자치구별 단지수·면적형수·세대수·미확정/제외 현황
- 주소/공식코드/특성 연결률과 미연결 대상
- official_gen_count와 관측세대수 차이; 차이를 억지로 보정하지 않기
- 엑셀·CSV·단지요약 간 합계 일치
- 개별 주택에서 단지·면적형 집계까지 추적 가능한 원천 행/키 대응

산술 합계가 맞는 것만으로 서울 전체 실제 재고의 완전성이 검증된 것은 아니다. 공시대상 누락, 유형 미분류, 특성 미연결, K-apt 매칭 부분집합을 따로 보고해줘.

[10. 최종 납품]
결과를 파일로 생성하고 최종 ZIP으로 묶어 제공해줘.

- 엑셀 seoul_apt_inventory_<연도>_<기준일>.xlsx
- inventory.csv (UTF-8 BOM, 소수 면적과 식별코드 원형 보존)
- model_ready.csv (세대수+기존 모형 필수 특성 완성 부분집합; 포함/제외 세대수 명시)
- id_crosswalk.csv
- source_manifest.csv (실제로 받은 자료만 성공으로 기록)
- source_attempts.csv (후보와 접근 실패·대체경로 기록)
- validation_report.xlsx 또는 동등한 상세 검증 파일
- review_needed.csv, excluded_records.csv 또는 대용량 Parquet
- 원자료/주택키→단지ID 대응의 감사 파일 또는 이를 재생성하는 코드
- 다운로드부터 집계·보완·검증·엑셀 생성까지 다시 실행할 수 있는 Python 코드
- 설정 파일, requirements.txt, README.md, 완료/미완료 상태와 실행 로그

대용량 파일은 DuckDB/Polars/청크 처리 등 적절한 도구를 사용해줘. 엑셀의 시트 행 제한을 확인하고 제한을 넘는 원자료/감사기록은 CSV·Parquet로 분리해줘. 무료 공식 대용량 파일이면 실제 확보를 시도하되, 불필요하게 동일 자료를 반복 호출하지 마.

원본 대용량 자료까지 최종 ZIP에 넣어 크기를 폭증시킬 필요는 없다. raw/에 보존한 파일과 해시·다운로드 주소 및 재확보 방법을 기록하고 최종 산출물은 전달 가능한 크기로 묶어줘.

최종 답변에는 사용한 기준시점과 공식 자료, 실제 확보 건수·단지수·면적형수·세대수, 모델 입력 완성도, 미확인 사항을 짧게 적고 결과 파일 링크를 제공해줘. 데이터를 못 받았으면 템플릿을 완성 데이터라고 부르지 말고, 확보 실패와 다음 단계 및 이미 작성한 코드를 제공해줘.

지금 패키지의 지침을 읽고 공식 자료 검색·다운로드부터 실제 작업을 시작해줘.
